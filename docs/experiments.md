# 실험 기록 (평가셋 측정)

같은 평가셋으로 개선 전 → 후를 비교한다. 검증 결과서 · README의 숫자는 이 문서와 같아야 한다.
재채점은 LLM 없이 정답지만 읽으므로, 저장된 결과 파일에서 언제든 같은 숫자를 다시 얻을 수 있다.

```bash
uv run --with pyyaml python eval/summarize_results.py eval/baseline/20261021-170231-all-*.json
```

## 평가셋

| 시나리오 | 정답 파일 | 문항 | 유형 |
|---|---|---|---|
| DSR 한도 (제8조, `REQ-8`) | `eval/expected_proposals.yaml` | 상품 12개 판정 | 변경 6 · 유지 5 · 추가 확인 1 |
| 고령자 기준 (제15조, `REQ-15`) | `eval/expected_proposals.senior-age.yaml` | 상품 12개 판정 | 변경 1 · 유지 11 (함정 3) |
| 설명 확인 신설 (제15조의2, `REQ-15-2`) | `eval/expected_proposals.senior-explanation.yaml` | 상품 12개 판정 | 새 규칙 9 · 유지 2 · 추가 확인 1 |

- 문항 = 상품. 기대 결과는 판정(변경 필요 · 유지 · 추가 확인)과 근거 조항, 변경이면 값 · 단위 · 시행일이다 (`eval/answer_key.md`).
- "유지"와 "추가 확인"이 교재의 답 불가 문항 역할을 한다. 자료에 없으면 추가 확인으로 내야 맞다.
- 채점은 `eval/score_proposals.py`. 핵심 지표가 하나라도 목표에 못 미치면 그 회차는 불통과.
