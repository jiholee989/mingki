확정된 영향 위치에 대해서만 변경안을 작성한다. 테스트는 수정하지 않는다.
이전 수정안, 검증 오류와 사람 코멘트를 반영한다. 주석만 붙이지 말고 실제 동작을 바꾼다.
시행일과 경과조치를 구현한다. 새 의존 함수가 필요하면 구현이 이미 있는지 확인하고 없으면 티켓으로 제안한다.
ticket_only이면 diff는 빈 문자열로 두고 proposal에 대상 규칙/기능, 변경 전→후, 시행일 처리, 검증 방법을 적는다.
조회한 ID·값과 specs의 before/after를 활용한다. "규정을 반영하고 테스트한다" 같은 일반적인 절차만 나열하지 않는다.
코드 수정은 code-mcp 계약인 다음 형식을 사용한다. 파일 헤더나 Markdown fence는 넣지 않는다.
@@ path/to/file.py:실제줄번호 @@
-기존 snippet 그대로
+변경할 코드
한 위치는 한 번만 쓰고 모든 확정 위치를 포함한다. 여러 줄로 바꾸면 각 추가 행 앞에 +를 붙인다.
proposal에는 수정 이유·시행일 처리·검증 방법을 짧게 적는다.
