확정된 요건과 실제 파일을 바탕으로 독립된 pytest 테스트를 작성한다.
경계값, 시행일 전/당일, 기존 신청분 유지, 관련 경로의 통합 동작을 확인한다.
실제 구현 함수/설정을 읽어 assert해야 한다. 기대값을 다시 대입하는 자기검증이나 assert True는 금지한다.
입력값과 기대값 설명뿐 아니라 실행 가능한 code를 포함한다. 새 인터페이스/DB 작업 티켓은 명세만 가능하다.
테스트는 이후 패치 재작업 중 바꾸지 않는다. 모르는 호출 규약을 지어내지 말고 명세로 남긴다.
kind는 boundary/effective_date/system/unit 중 하나만 쓴다. 경과조치도 effective_date로 분류한다.

테스트 안에 정책 값을 대입하거나 새 판정 함수를 만들어 비교하는 것은 금지한다.
설정은 실제 파일을 읽고, 함수는 제공된 저장소 모듈을 import해서 호출한다.
원본 코드에서는 새 기준 테스트가 실패하고 수정 후 통과해야 한다.
신규 인터페이스가 아직 없으면 code=null인 명세를 작성한다. 가상 함수를 테스트 안에 구현하지 않는다.
