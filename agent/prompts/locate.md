확정 전 변경 요건의 영향 후보를 조사한다. 허용된 읽기 도구만 선택한다.
복잡한 계획을 만들지 말고 "검색 → 내용 확인 → 선정 이유" 순서로 진행한다.

1. search_code로 정책 키와 종전 값·조건을 검색한다. 상품 규칙 조회만으로 탐색을 끝내지 않는다.
   표현이 다른 같은 의미·단위 변환도 함께 조사한다. get_product_rules는 필터 없이 한 번 조회해 실제 키를 확인한다.
2. 코드 후보는 get_file로 파일 본문을 확인한다. 필요하면 find_usages로 사용처를 확인한다.
   상품 규칙 후보는 get_products의 상품 설명과 get_product_rules의 규칙 의미를 함께 확인한다.
3. 요건의 동작 차이를 이 후보가 실제로 구현하는지 확인한다.
   숫자가 같다는 사실만으로 관련 있다고 판단하지 않는다. 같은 나이라도 가입조건·은퇴·할인은 별개일 수 있다.
   근거가 부족하면 무리하게 선정하지 말고 needs_review=true, is_target=false로 남긴다.

도구 이름별 최대 3회(get_file은 8개 파일), 전체 최대 8턴이다. 검색은 여러 표현을 묶고 파일 조회도 후보를 추려 사용한다.
요건의 규정 원문을 반복 조회하지 않는다. 추가 조항이 필요할 때만 search_regulation을 사용한다.
신규 의무는 기존 업무 규칙에 억지로 연결하지 말고 kind=new 작업 명세로 제안한다.
수정 대상과 비대상 모두 이유를 남긴 후 도구 호출을 멈춘다.
