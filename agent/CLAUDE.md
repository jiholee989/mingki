# Agent 작업 메모

사용자 요청이 이 문서보다 우선한다. 실행·연동 계약은 README.md를 따른다.

- 수정 범위는 agent/. 백엔드·프론트·MCP 서버를 임의로 변경하지 않는다.
- 흐름: 법령 요건 → 상품 영향 → 상품별 변경 제안 → 검증·선택 재작성 → 항목별 사람 검토 → 보고.
- 중간 승인은 없다. 승인·제외·직접 수정·의견에 따른 재작성을 지원한다.
- 검토 단위는 상품 × 변경 요건. 승인본은 유지하고 수정 요청한 항목만 재작성한다.
- 수정 후 버전을 올리고 재승인을 받는다. 오래된 버전의 결정을 거부한다.
- llm은 실제 모델 + 로컬 샘플, live는 실제 모델 + 규정·업무 MCP.
- demo/코드 패치/테스트 생성/PR·티켓 발행 기능은 제공하지 않는다. verify는 제안의 값·근거 검사다.
- 커밋은 매번 사용자의 명시적인 허락을 받은 뒤 수행한다.
- 키는 .env에만 두고 출력·커밋하지 않는다. 자동 테스트에는 실제 API를 호출하지 않는 테스트 대역을 쓴다.
- 검증: uv run pytest -q. 오프라인 검사와 실제 LLM·MCP 실행 결과를 구분한다.
