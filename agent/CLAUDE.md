# Agent 작업 메모

실행·구조·연동 계약은 README.md를 따른다. 사용자 요청이 이 문서보다 우선한다.

- 범위: `agent/`. 다른 팀의 backend/frontend/MCP 서버는 계약 확인 없이 바꾸지 않는다.
- 흐름: 요건 추출 → 영향 탐색 → 첫 승인 → 테스트 → 순차 수정안 → 검증 → 최종 검토 → 발행.
- 첫 승인에서 변경 근거와 영향 위치를 함께 보여준다. 승인 전 수정안은 만들지 않는다.
- LLM 판단은 `Reasoner`, 외부 기능은 `Tools` 인터페이스로 분리한다.
- demo의 고정 규칙·코드 목록을 실제 분석 성능으로 취급하지 않는다.
- 테스트는 최초 생성 후 재작업에서 고정한다. 시스템 실패/실행 수 0건은 발행 차단이다.
- 변경 도구는 publish에만 제공하고 Spring 승인 ID를 전달한다.
- 최종 승인 후 patch를 잘라내지 않는다. 제외/수정은 재작성·재검증 후 새 승인이다.
- 키는 `.env`에만 둔다. 실제 API 호출은 명시적 llm/live 모드에서만 수행한다.
- llm 모드는 실제 모델 + 로컬 샘플 조회다. MCP 없이 실행하며 검증·발행을 수행하지 않는다.
- 검사: `uv run pytest -q`. 오프라인 테스트 통과와 실서비스 연동 성공을 구분해 보고한다.
